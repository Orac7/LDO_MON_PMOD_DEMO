# CLAUDE_REVIEW

Automated design review of `LDO_MON_PMOD_Board_V1`, generated by Claude (Anthropic's Claude Code CLI) at the request of the repository owner.

**This is not a sign-off.** It is a machine-assisted second pair of eyes. It does not replace your own review, a peer review, or the fabricator's DFM check. Findings tagged `judgement` are opinion and may be wrong; findings tagged `tool` come straight from `kicad-cli` and are authoritative.

## Contents

| Path | What it is |
|---|---|
| `REVIEW_LOG.md` | Append-only record of every check run, its method, and its verdict — including checks that could not be completed and why |
| `FINDINGS.md` | The deliverable: ranked, verified issues with refdes and suggested fix |
| `scripts/` | Every script used, retained so the review is re-runnable and auditable |
| `raw/` | Tool output and parsed intermediates the review is based on |
| `datasheets/` | Vendor datasheets used for parameter checks. **Not committed** — see the manifest below |

## Re-running

```sh
./scripts/01_run_kicad_checks.sh      # ERC, DRC+parity, netlist, BOM -> raw/
./scripts/02_strict_checks.sh         # same, with all suppressed rules re-enabled
python3 scripts/03_extract_tables.py  # components.tsv, nets.tsv, net_summary.md
./scripts/04_fetch_datasheets.sh      # datasheets (some vendors block; see log)
```

Scripts are read-only with respect to the design. `02_strict_checks.sh` works on a temporary copy of the project and never modifies `LDO_MON_PMOD_Board_V1/`.

## Method tags used in the log

- `tool` — output of `kicad-cli`; authoritative
- `parse` — deterministic analysis of the KiCad s-expression files by a retained script
- `judgement` — Claude's reading of design intent against a datasheet or convention; treat as opinion

## Script caveats

`05_plane_return_path.py` and `06_pcb_geometry.py` were written by a Wave 1 reviewer and audited in Wave 2. Known defects, documented rather than silently fixed so their output is not over-trusted:

- `05` measures only whether a track centreline leaves copper. It **cannot distinguish a trace crossing a plane gap from one running parallel alongside it**, does no cause attribution, never measures slot width, and truncates its per-net example list to 4 entries. That truncation is why its first run reported F.Cu as clean when F.Cu in fact has more off-copper stretches than B.Cu. Findings built on it were demoted accordingly.
- Both scripts *do* correctly parse zone `filled_polygon` geometry — an early hypothesis that they ignored zone fills was tested and disproved.

Treat `05`'s output as a screening pass, not a measurement.
